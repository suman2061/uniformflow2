# UniformFlow - Project Instructions

## Overview
Multi-tenant SaaS platform for school uniform suppliers in India. Phase 1 = Core Foundation.

## Visual Style
- Primary: Indigo (HSL 239 84% 67%)
- Design: Enterprise B2B SaaS with clean, professional look
- Font: Inter (system) + display headings
- Currency: INR (₹) everywhere
- Timezone: Asia/Kolkata display, UTC storage

## Architecture
- Multi-tenant: businessId derived from JWT session, NEVER from client
- 7 RBAC roles: SUPER_ADMIN, BUSINESS_OWNER, BUSINESS_ADMIN, OPERATIONS_MANAGER, ACCOUNTS_MANAGER, DATA_ENTRY_OPERATOR, READ_ONLY
- lib/tenant.ts: requireTenant() / requireSuperAdmin() for API route guards
- lib/rbac.ts: hasPermission() for UI + checkPermission() for API
- lib/audit.ts: createAuditLog() + diffChanges() for all mutations
- lib/permanent-id.ts: UF-XXXXXX format student IDs with atomic increment

## Demo Data

- Demo login: demo@uniformflow.app / Demo@1234

## Routes
- /login, /signup — public auth pages
- /dashboard/* — tenant-scoped pages (schools, students, products, school-products, users, audit-log)
- /admin/* — super admin only (businesses, demo-data)
- /api/* — all API routes

## Key Rules
- Never proceed to Phase 2 without user approval
- signOut uses redirectTo (Auth.js v5)
- Signup creates Business + BUSINESS_OWNER user
- Super Admin has businessId=null
- All isDemoData records can be bulk-removed via super admin
